### General Reflection

When I sat down to choose my learning goals I made sure to choose goals I thought were realistically achievable, challenging, and beneficial in the long term.

As I discuss below, I believe the goals I chose are very closely aligned with my job tasks while also being generally applicable to other software development roles I will be in in the future.

In this work term I learned a lot about numerous technologies I had never used or even heard of before. Many of them I used, others I learned about as it was still pertinent to performing my job properly. The technologies are as follows:

<Steps>
    1. **.NET & ASP.NET Core** (C#, EntityFramework, Visual Studio, WPF) 2. Web
    (Bootstrap, Blazor Server, Blazor WASM)
</Steps>

### Goals I set at the beginning of the work term

<Steps>
    1. **Depth & Breadth of Understanding**: 
        In my first co-op term with this company I learned many new technologies and
        skills. Because I was learning so many new things my learning was ultimately
        shallow and not very deep. This work term I'd like to prioritize gaining a
        deeper understanding of the new things I have learned.
    2. **Problem Solving**: 
        In my first work term with this company, I was assigned a relatively complex
        project to implement a library communication protocol for machine-to-machine
        autonomous communication. In my first work term I did not complete much of the
        project as it was not a priority and some of the requirements were ambiguous.

        In this work term I aim to go beyond just writing code but to employ my problem
        solving skills to architect & finally complete the project.

    3. **Written Communication**:
        I want to improve my technical documentation skills. I have not spent much time
        doing this in the past so I want to develop this skill now.

</Steps>

### My attempt achieving those goals and what I learned

<Aside>
    Much of this reflection has been pulled directly from my 'Learning Goals'
    document on Experience Guelph
</Aside>

<Steps>
1. **Depth Integrative Communication Breadth of Understanding**: For this goal I wanted to choose a few specific technologies and really learn about them in-depth. I set my measure of success to be the point at which I feel I am more comfortable using the technology I chose. Comfortable in not only using it, but working in its ecosystem. For this past work term I chose this technology to be .NET and ASP.NET Core more specifically.  Having worked with these technologies for the past 8 months I feel I am competent in using them. I am comfortable using and navigating the .NET ecosystem. I have improved my full-stack skills and have learned another method to create & deploy web applications. I have also spent some time learning about the CLR and C# compiler, Rosyln. This has given me a good foundation in the .NET ecosystem.

2. **Problem Solving**: As mentioned above, for this goal I wanted to put more effort into my problem solving skills and take my in-progress project to completion. I made a plan of looking at the project from a more comprehensive viewpoint. Instead of getting bogged down on hyper specific implementation details, I'd work on the general architecture and try to implement that. If issues came up, I'd solve them along the way. I successfully created an architecture for the project and then proceeded to implement it myself. I was able to bridge the existing code with my new implementation and create one seamless platform for the project. While the project is not complete, I was able to contribute the majority of the work required to complete the project.

3. **Written Communication**: This goal was essentially about leaning how to write proper and readable technical documentation. My action plan for this was to research how to write in this manner, and then implement it at work in the projects I was working on. I knew I would be successful when I felt I had a better grasp on effectively communicating technical concepts through documentation. I initially intended to research technical writing and maybe take a course offered by Google. I was not able to do this due to time restraints. I was however able to practice technical writing while doing my job. This semester, I wrote comprehensive READMEs (and sometimes additional documentation) for all of the projects I contributed a significant amount of work towards. I know the struggle of dealing with an undocumented codebase do I tried my best to include all necessary information for a new person to begin working on the project. 


</Steps>
